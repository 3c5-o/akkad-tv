# أكّد | AKKAD TV

منصة IPTV بواجهتين منفصلتين: **أكّد للمستخدم (أفقي)** و**أكّد للإدارة (عمودي)**، مع لوحة تحكم API وقاعدة بيانات Supabase. التصميم مبني على الهوية السوداء والذهبية المرجعية.

> هذا المستودع عام. **لا تحفظ بيانات مصادر IPTV أو المفاتيح السرية أو كلمات المرور هنا.**

## البنية
- `server.mjs` — خادم Node.js بدون حزم إضافية، واجهات API، والمصادقة عبر Supabase.
- `public/tv.html` — واجهة المستخدم الأفقية.
- `public/admin.html` — لوحة الإدارة العمودية.
- `public/akkad.css` و`public/akkad.js` — هوية مشتركة وتفاعل.
- `supabase/migrations/0001_init.sql` — الجداول وRLS وRPC والاشتراكات.
- `cloudflare/worker.js` — مسودة بوابة API (لا تنشر قبل ضبط BACKEND_ORIGIN).
- `design/REFERENCE.md` — تعليمات مطابقة التصميم المرجعي.
- `android/README.md` — خطة البناء الأصلي والتوقيع.

## التشغيل المحلي
```bash
node server.mjs
```
افتح http://localhost:3000/tv و http://localhost:3000/admin .

## متغيرات البيئة
```
PORT=3000
SUPABASE_URL=https://evjagbqowyveizuylgnu.supabase.co
SUPABASE_PUBLISHABLE_KEY=...
```
استخدم Railway Variables لهذه القيم. المفتاح المنشور صالح في بيئة عميل حسب سياسات RLS؛ **لا تستخدم service_role في المتصفح أبداً**.

### الحالة
الواجهات وAPI الأولي هي أساس تطوير وتشغيل قابل للاختبار، وليست إصدار APK نهائي أو خدمة محتوى حي مكتملة. تسجيل الدخول يعمل بعد ضبط Supabase Auth ومتغيرات الخادم. يتطلب تشغيل البث إضافة روابط مصادر مرخّصة من لوحة الإدارة وضبط استحقاقات المستخدمين. تحميل الفيديو من المصادر يعتمد على توافق البروتوكول والصيغ وحدود المزود.

## المدير الأساسي
`akkadtv10@gmail.com` موجود في Auth، وملف الترحيل يُنشئ عضوية super_admin برقم UUID الخاص بهذا الحساب الموجود بالفعل (وليس عبر مقارنة البريد ضمن طلبات API). لا يُمنح الدور لأي تسجيل جديد بناءً على البريد وحده.

## الأمان
RLS لجميع الجداول، التحكم بالأدوار من الخادم، لا أسرار في GitHub، فحص ترخيص مصادر IPTV، وفصل البث الخاص بالمشتركين عن بيانات الكتالوج العامة.
