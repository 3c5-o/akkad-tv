# إدارة مصادر IPTV في أكّد — المرحلة الثانية

هذه المرحلة تدعم **فهرسة المحتوى المرخّص** من Xtream API وM3U، ولا تتجاوز حدود اتصالات أي مزوّد ولا تمنح حقوقاً إضافية لإعادة التوزيع.

## 1. إعداد أمان الخادم (مرة واحدة لكل مزود)
داخل Railway → مشروع `akkad-tv` → خدمة `akkad-core` → Variables أضف:

```text
AKKAD_ALLOWED_SOURCE_HOSTS=iptv.example.com,second.example.net
```
استبدل الأمثلة بالنطاقات أو عناوين IPv4 العامة الفعلية لمزودي البث الذين لديك تصريح باستخدامهم، **دون** `http://` أو `https://` أو منفذ أو اسم مستخدم أو كلمة مرور. تظل عناوين الأجهزة الخاصة والمحلية مرفوضة، حتى لو أضيفت إلى قائمة السماح.

مفتاح `AKKAD_SOURCE_ENCRYPTION_KEY` مضبوظ مسبقاً داخل Railway لتشفير الحسابات. لا ترفعه إلى GitHub، واحفظ نسخة آمنة خاصة من المفتاح لاستعادة البيانات عند الانتقال إلى خادم جديد. تغيير المفتاح يجعل بيانات الاعتماد القديمة غير قابلة للفك، لذا يتطلب خطة تدوير.

## دعم HTTP التجريبي لمزودي Xtream/M3U

أضف متغير الخادم إلى Railway:

```text
AKKAD_ALLOW_HTTP_SOURCES=true
```

الاختيار منفصل لكل مصدر عبر خيار «السماح لـHTTP غير المشفر لهذا المصدر فقط» في نموذج الإدارة؛ حسابات HTTPS لا تتأثر. اسم مستخدم Xtream وكلمة المرور أو رابط M3U الكامل يُحفظ مشفراً AES-256-GCM في Supabase، **لكن عند الاتصال بمزود HTTP يتم إرساله عبر الشبكة من Railway إلى المزود من دون تشفير**، وقد يراه طرف ثالث على المسار. لا تُستخدم هذه الطريقة للحسابات الحساسة إذا كان HTTPS متاحاً. لا تنشر بيانات الحساب في GitHub أو روابط المشاركة.

ملاحظة: رابط البوستر/التشغيل في تطبيق الويب يبقى محتاجاً إلى HTTPS متوافق أو وسيط بث مصرح وآمن؛ دعم فهرسة HTTP لا يعني أن الفيديو سيعمل مباشرة في متصفح يستخدم HTTPS بسبب قيود المحتوى المختلط.

## 2. من لوحة الإدارة العمودية
1. افتح `/admin` وسجل بحساب المدير الأساسي.
2. مصادر IPTV → أضف مصدر Xtream أو M3U مرخصاً بعنوان خادم `https://provider.example` أو `http://provider.example:8080`، دون اسم مستخدم أو كلمة مرور أو معاملات وصول في رابط الخادم. عند HTTP فعّل مربع الموافقة على النقل غير المشفر لهذا المصدر.
3. بعد الإضافة اختَر المصدر في قسم «فحص حسابات IPTV والمزامنة».
4. أدخل اسم مستخدم وكلمة مرور Xtream، أو رابط M3U الكامل؛ ثم اضغط «حفظ بيانات الحساب بأمان». تُحفظ المعلومات مشفّرة AES-256-GCM في قاعدة البيانات؛ الواجهة لا تعرضها مجدداً.
5. اضغط «فحص المصدر». تتطلب هذه الخطوة نجاح المصادقة ووجود النطاق في `AKKAD_ALLOWED_SOURCE_HOSTS`.
6. اختَر «القنوات / الأفلام / المسلسلات»، ثم حد 10 أو 50 أو 100، ثم اضغط «بدء مزامنة القسم».
7. راجع قسم «المحتوى» لنشر عناصر الكتالوج الصحيحة بعد التحقق.

## 3. ماذا يفعل المحرك؟
- يستخدم HTTPS افتراضياً، ويسمح لـHTTP فقط إذا تحقق شرطان: موافقة المدير المحفوظة على مستوى هذا المصدر، وتفعيل `AKKAD_ALLOW_HTTP_SOURCES=true` في Railway. يتحقق من السماح باسم النطاق/IPv4 العام، وعناوين DNS، ويرفض التحويلات HTTP redirect. لا يتيح قائمة مضيفين مفتوحة.
- Xtream: يستخدم `player_api.php` لجلب معلومات الاشتراك وقائمة أقسام Live/VOD/Series.
- M3U: يقرأ بيانات `#EXTINF` ويصنف العناصر وفق المجموعة.
- يضيف المحتوى **كبيانات وصفية ومسودات**، ولا يستورد روابط بث أو رموز الوصول ضمن الكتالوج العام.
- يخزّن خريطة `source_id + kind + external_id` ويربطها بمحتوى أصلي، مع مفتاح إزالة تكرار متحفظ يعتمد على TMDb ID أو العنوان والسنة عندما تتوفر.
- يعرض أعداد العناصر المحفوظة، وسجل المزامنة، والأخطاء المختصرة التي لا تكشف كلمات المرور.
- يُقيّد مهمة مزامنة واحدة لكل مصدر وقسم، مع معالجة المهام المتروكة أكثر من 10 دقائق.

## 4. قيود المرحلة الحالية
- لا توجد مصادر حقيقية مُضافة حالياً في قاعدة بيانات أكّد، ولم تُختبر حسابات خارجية فعلية.
- هذه **مزامنة معلومات المحتوى** وليست بثاً مباشراً جاهزاً؛ ربط المسلسلات بمواسمها وحلقاتها، وتحويل مصادر Xtream إلى جلسات تشغيل ذات صلاحيات وحدود اتصال ما زال في المراحل التالية.
- كل طلب يزامن 10 أو 50 أو 100 عنصر، ويستكمل تلقائياً من الموضع المحفوظ في آخر دفعة ناجحة. لتحديث ترتيب مكتبة تغيّر عند المزود، فعّل «إعادة من بداية القائمة». لا توجد مهام خلفية تلقائية لاستيراد آلاف العناصر دون تدخل الإدارة بعد، وقد تحتاج القوائم الكبيرة إلى دفعات كثيرة.
- روابط تشغيل الفيديو المباشرة لا تُرسل تلقائياً إلى مستخدم التطبيق، حتى لا تُكشف بيانات مزود البث.
- HTML5 يختلف عن Android Media3 في دعم MKV والترجمات والصوت.
- يلزم لاحقاً مراجعة دقة الدمج عبر المصادر، وإمكانية الفصل اليدوي للأعمال ذات العنوان المتطابق.

## 5. واجهات API المحمية
تتطلب جميع هذه الطلبات توكن Supabase صالحاً لمدير أكّد:
- `POST /api/admin/sources/:id/credentials`: حفظ كلمة مرور Xtream أو رابط M3U المشفّر.
- `POST /api/admin/sources/:id/check`: فحص اتصال مزود البث.
- `POST /api/admin/sources/:id/sync`: جسم `{"kind":"movie","limit":50}`.
- `GET /api/admin/sources/:id/jobs`: سجل آخر 20 عملية.

## 6. قائمة اختبار يدوي عند أول مصدر حقيقي
اختبر مصدراً مرخصاً واحداً فقط، وأكد: نجاح المصادقة، تاريخ الانتهاء، الحدود، أعداد الأقسام، مزامنة 10 عناصر، تكرار الطلب دون نمو مكرر، نشر عنصر واحد، ومنع الدخول إلى إعدادات المصدر بدون صلاحية المدير.
