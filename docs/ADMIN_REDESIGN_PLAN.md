# أكّد — حالة تحديث الإدارة والمستخدم

## التسليم المنجز في GitHub
- تصميم لوحة الإدارة العمودية مجدداً باستخدام \`public/admin.html\` و\`public/control.css\` و\`public/control.js\`.
- لوحة مؤشرات للمصادر المتصلة وغير المتصلة، مع حالة المصدر، تاريخ انتهاء الصلاحية والأعداد الحقيقية المحفوظة من المزامنة.
- صفحة إدارة المصدر: فحص قبل الإضافة، تعديل الاسم/العنوان، إيقاف/تشغيل بعد فحص ناجح، حذف بتأكيد المدير الأساسي، رمز مجاني 2–12 رمزاً مثل \`A1\`، إعداد المزامنة التلقائية والنشر التلقائي.
- صفحة الكتالوج مع فلترة والبحث والنشر/الإخفاء.
- باقات واشتراكات وأكواد VIP.
- إعداد مفتاح TMDb v3 أو Read Access Token من صفحة الإدارة، مع اختبار الاتصال، تخزين AES-256-GCM داخل Supabase، وعدم إعادة عرضه.
- واجهة المستخدم الأفقية: الدخول باسم مستخدم وكلمة مرور من إنشاء الإدارة؛ تحتها خيار مصدر مجاني مع إدخال \`A1\`. لا توجد واجهة إنشاء حساب عام.
- API لإدارة حسابات المشاهدين مع إنشاء وتوقيف/حذف وتغيير كلمة المرور (يتطلب مفتاح Supabase Service Role الخادمي).
- محرّك فهرسة محتوى Xtream/M3U تلقائياً بدفعات 50 لكل قسم، مع محاولة إثراء TMDb وعدم تكرار المحتوى بنقل metadata، ومؤشرات تقدم؛ التشغيل المشروط بخادم ذي صلاحيات مأذونة.
- قاعدة البيانات محمية بسياسات RLS؛ الوصول للكتالوج الخاص يحتاج مستخدماً مُداراً نشطاً، والبث يتطلب اشتراكاً نشطاً. كود المصدر المجاني يعرض بيانات وصفية مرخصة منشورة عن طريق RPC خاص.

## ما يلزم تفعيله يدوياً
داخل Railway > akkad-tv > akkad-core > Variables:
- \`SUPABASE_SERVICE_ROLE_KEY\`: أضف قيمة \`service_role\` من إعدادات مشروع Supabase أكّد. لا ترسلها في المحادثة ولا تحفظها داخل GitHub ولا داخل الواجهة.
- \`AKKAD_USERNAME_SECRET\`: تم ضبطها على Railway؛ لا تغيّرها بعد بدء إنشاء المستخدمين كي لا يتغير البريد الداخلي المشتق.
- \`AKKAD_SOURCE_ENCRYPTION_KEY\`: موجودة مسبقاً على Railway؛ تغييرها بدون تدوير سيمنع فك بيانات مزودي IPTV وTMDb.
- \`AKKAD_ALLOWED_SOURCE_HOSTS\`: قائمة نطاقات المزودين المسموحة فقط. كل مصدر جديد يحتاج إضافة نطاقه أو IP العام إلى القائمة.
- TMDb: المفتاح نفسه يُضاف من صفحة TMDb داخل لوحة الإدارة، ليس من GitHub.

القاعدة: لا تفعّل \`auto_import\` على مصدر حتى ينجح فحص الاتصال، يُثبت الترخيص، وتُضبط صلاحيات الخادم. \`auto_publish\` ينشر البيانات الوصفية وليس روابط تشغيل الفيديو بذاتها.

## حدود الإصدار الحالي
- مصادر Xtream HTTP تنقل بيانات تسجيل الدخول إلى مزود HTTP دون TLS؛ التخزين المحلي مشفر، لكن الشبكة الخارجية غير مشفرة. استخدم HTTPS إذا وفره المزود.
- لا توجد بيانات اعتماد محفوظة للمزودين الأصليين وقت الفحص، لذلك اختبارات الحساب الحقيقي لم تتم بعد.
- اختبار حسابات المشاهدين ينقصه \`SUPABASE_SERVICE_ROLE_KEY\` وأول حساب فعلي من الإدارة.
- إدخال \`A1\` يفتح الكتالوج المجاني المرخّص فقط. التشغيل المباشر من Xtream HTTP يتطلب بوابة بث آمنة وصلاحيات وحزم وقياس استهلاك؛ **لم يُعلن مكتمل التشغيل**.
- الإثراء من TMDb انتقائي عند تطابق العنوان والسنة، ويتطلب مفتاحاً صالحاً.
- المواسم والحلقات والمشغل الأصلي Media3 وإصدار APK وتوقيعه، واختبارات Android TV الشاملة، لم تكتمل بعد.
- الواجهة التجريبية تعتمد على المتصفح الحالي وRailway؛ GitHub CI يختبر التركيب ومسارات API الأساسية، وليس التجربة على جهاز فعلي.
